# 35mm — Acceptance Criteria

## Landing
- AC-001: El visitante visualiza la identidad visual y experiencia dinámica existente.
- AC-002: La landing es responsive.
- AC-003: La landing existente no se reemplaza por una plantilla genérica.

## Información
- AC-004: Se puede consultar la información principal del festival.
- AC-005: Se pueden visualizar fechas importantes.
- AC-006: Se pueden consultar reglas.
- AC-007: Se pueden consultar ediciones y ganadores.

## Inscripción
- AC-008: El visitante puede abrir el formulario propio.
- AC-009: Los campos obligatorios se validan antes del envío.
- AC-010: El backend valida nuevamente la información.
- AC-011: Una inscripción válida se almacena correctamente.
- AC-012: El líder recibe un correo de confirmación después de una inscripción exitosa.
- AC-013: Una inscripción guardada no se pierde si falla el envío del correo.
- AC-014: El usuario recibe feedback claro después del envío.

## Cortometraje
- AC-015: La plataforma no almacena el archivo de video.
- AC-016: El participante puede acceder al Google Forms destinado al cortometraje.

## Administración
- AC-017: Un administrador autenticado puede acceder al dashboard.
- AC-018: El administrador puede visualizar el total de inscritos.
- AC-019: El administrador puede consultar las inscripciones.
- AC-020: El administrador puede descargar la información en Excel.
- AC-021: Un usuario no autorizado no puede acceder al dashboard ni al endpoint de exportación.

## Seguridad
- AC-022: No existen secretos en el repositorio.
- AC-023: CORS está restringido al frontend autorizado.
- AC-024: La aplicación funciona mediante HTTPS en producción.

## No funcionales
- AC-025: El sitio respeta `prefers-reduced-motion`.
- AC-026: La navegación básica funciona mediante teclado.
- AC-027: Los formularios tienen labels y mensajes de error accesibles.
- AC-028: Las animaciones y composición visuales existentes se conservan salvo justificación técnica documentada.
